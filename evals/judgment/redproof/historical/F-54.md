Inside their own workspace, whose actions does a user see?

- (a) **All members' actions** — workspace-wide trail ← ✅ recommended (the plain reading of your correction; what the spec currently assumes)
- (b) **Own actions only** — the read endpoint and scenario set narrow accordingly

*This is the intake's one recorded open assumption — it needs an explicit ruling. If your decision changes the user story, I will mirror a note to issue #54.*

**[em] · Q2 · Audit-write failure semantics**

If the audit insert fails after the business action succeeded, what happens?

- (a) **Best-effort** — the action commits; the audit loss is logged loudly server-side ← ✅ recommended
- (b) **Atomic** — audit write joins the same transaction; the user sees an error

*The driver is operational traceability, not compliance — best-effort matches; but atomicity is cheap for same-DB writes, so it is your call. Intake explicitly deferred this.*

**[em] · Q3 · Auditable-operation survey**

Four ambiguous cases need rulings — answer like 3a/3b/3c/3d:

- **(3a) Bulk pipeline-config import**: one record **per imported config** ← ✅ recommended · or one per import request
- **(3b) Bucket bulk operation**: one record **per bucket** ← ✅ recommended · or one per request
- **(3c) Approval-request execute**: log **the resulting entity change only** ← ✅ recommended · the execute action · or both
- **(3d) Async background-handler trigger**: **excluded** (internal hook, not a user-console action) ← ✅ recommended · or included

*Per-entity records keep the trail answerable at the object level; the async handler has no acting console user.*

**[em] · Q4 · Workspace attribution for global entities (story-level)**

Clusters, domains, and products have no owning workspace — 'every action recorded' and 'viewable within one's workspace' cannot both hold for them. Their records are:

- (a) **Recorded with null workspace, invisible via this endpoint** ← ✅ recommended (the contract's current pending choice)
- (b) Visible to everyone
- (c) Attributed to the acting user's workspace(s)

*(a) keeps recording complete and the read boundary intact; a global-entity viewer can be a later sibling. If your decision changes the user story, I will mirror a note to issue #54.*
