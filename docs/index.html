A human-gated AI development pipeline人類把關的 AI 開發流水線

Roz Gate turns a repository into a role-driven pipeline run by specialized AI agents — a product advocate, an engineering manager, an implementer, a blind black-box QA, an independent reviewer. Agents do the work. You make every decision that matters: the pipeline stops at explicit gates and cannot cross them without you. And it's team-ready: anyone can weigh in on an intake thread, but authority stays pinned — the issue assignee asks for the summary, and their gate label is the confirmation that files the story.

Roz Gate 把一個 repository 變成由專職 AI agents 運轉的角色驅動流水線——產品代言人、工程經理、實作者、看不到實作的黑箱 QA、獨立審查者。工作由 agents 完成,但每個重要決定都是你的:流水線在明確的 gate 前停下,沒有你就過不去。而且它是為團隊設計的:intake 討論串任何人都能參與,但權威固定不動——由 issue assignee 召喚 summary,他貼上的 gate label 就是成案的確認。

The team — fixed seats, swappable occupants團隊——席位固定,入座可換

Six roles run the loop. The five specialist names are seats — workflow vocabulary that never changes. Who actually sits in a seat is per-project config (the ### Roz Gate personas block): link an agent you already own — implementer: backend — or keep the plugin default. Every dispatch attaches the seat's Owns/Never contract, and init lints a linked persona against it. Persona is swappable; the contract never is. Click a role.

六個角色運轉這個 loop。五個專職名稱是席位——workflow 的詞彙,永不改變。席位上實際坐誰是每專案的配置(### Roz Gate personas block):連結你已有的 agent——implementer: backend——或用 plugin 預設。每次派工都附上席位的 Owns/Never 契約,init 連結時會對照檢查。Persona 可換,contract 不換。點任一角色。

The loop — click any stage or gate流程地圖——點任一階段或 gate

Gold fences are gates: only you open them, by applying a label or merging. Everything between the fences runs itself.

金色柵欄是 gate:只有你能開——貼上 gate label 或 merge。柵欄之間的一切自己運轉。

⚠️ Escalation valve: the moment a fast change grows a real decision — user-facing behaviour, a choice two engineers would make differently — it is relabelled track: spec + ready-for-spec and rejoins the spec loop at (2). Nothing recovers a design shipped through the fast track, so when in doubt: spec. ⚠️ 升級閥:fast 變更一旦長出真正的決定——使用者可見的行為、兩位工程師會做出不同選擇的地方——立刻改掛 track: spec + ready-for-spec,從 (2) 重新加入 spec 迴圈。從 fast track 出貨的設計沒有機制能救,所以猶豫時:選 spec。

Labels — who applies what, and when標籤——誰貼、何時貼

One rule underneath everything: gate labels are authorizations — only you move them. Transient labels are status reports — only the machine moves them. Neither ever touches the other's. Click a label.

底層只有一條規則:gate label 是授權——只有你能動;transient label 是狀態回報——只有機器能動。兩邊永不越界。點任一標籤。

Optionally, the agent can act under its own bot identity (GitHub App / GitLab project access token) instead of your account — you can tell who's speaking, its questions actually notify you, and your credentials stay out of its hands. A bot never holds a gate. One-time setup: references/identity-github-app.md.

另可選配:讓 agent 以自己的 bot 身分行動(GitHub App / GitLab project access token)而非你的帳號——看得出誰在說話、它的提問會真的通知你、你的憑證不落它手。bot 永遠不是 gate holder。一次性設定:references/identity-github-app.md。

Rules with teeth — bundled PreToolUse hooks有牙齒的規則——隨附的 PreToolUse hooks

The rules that protect you from the agents are not just prose: bundled hooks enforce them before the tool runs, fail-closed, with a message that tells the agent the remedy. Prompt discipline is the manners; the hook is the law.

保護你不被 agent 越界的規則不只是紙上的:隨附的 hooks 在工具執行前就擋下,fail-closed,訊息直接告訴 agent 該怎麼補救。Prompt 的自律是禮貌;hook 才是法律。

How we know it works我們怎麼知道它有效

Three tiers of evidence live under evals/ (the ledger). Every case derives from a defect that actually shipped, or its identical shape — and a new case counts only after it has been seen red first.

三層證據放在 evals/(the ledger)。每個 case 都來自一個真的出過的 defect,或同形狀的預防檢查——而且新 case 要先被看到紅過才算數。

lintstatic checks on the plugin's own prose and hook code, on every push: the rule itself being broken is the failure mode compliance testing can't see.對 plugin 自己的 prose 與 hook 程式做靜態檢查,每次 push:「規則本身壞了」是 compliance testing 看不到的失敗模式。
replaythe real commands run headless in a sandbox against a stateful forge stub, graded by code; pass^k with Wilson intervals — rates, never booleans; an invalid run is never a red.真的 command 在 sandbox 裡對著有狀態的 forge stub 跑,由程式打分;pass^k 加 Wilson 區間——是比率不是布林;invalid 永遠不算紅。
judgmentLLM-as-judge on real historical issues frozen at the moment before the loop ran: "did it surface what changed the human's mind" — quote-verified, recall and precision reported separately.LLM-as-judge,對凍結在 loop 跑之前那一刻的真實歷史 issue:「它有沒有提出後來改變人類想法的事」——引用需可驗證,recall 與 precision 分開報。

The release gate runs lint and the hook unit tests on every push. The opus baseline as of 2026-09-21: replay 17/18 cases at 100% (k=5), F6 no in-session decay across three 12-turn sessions; judgment at k=2, F-63 recall 1/2 · precision 1/2 against the historical run's 2/2 · 0/2. Every case derives from one repository and one operator — green proves no regression on work shaped like that, nothing about shapes never run.

release gate 每次 push 都跑 lint 與 hook 單元測試。opus baseline(2026-09-21):replay 18 個 case 中 17 個 100%(k=5),F6 三個 12 輪的 session 內沒有衰退;judgment k=2,F-63 recall 1/2 · precision 1/2,對照歷史那次的 2/2 · 0/2。所有 case 來自同一個 repo、同一位 operator——全綠證明的是「像那種形狀的工作不退化」,對沒跑過的形狀什麼都不證明。
